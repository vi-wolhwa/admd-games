## 1. 계승하는 뼈대

> **한 땅, 두 그라운드. 차분한 바탕 위에서, 게임과 사람이 움직일 때만 떠오른다.**

| 계승 요소 | 이유 |
| --- | --- |
| 두 그라운드 한 체계 — 구조·컴포넌트는 같고 강조색 세트만 `[data-ground]` 로 전환 | 두 사이트가 하나로 느껴지면서 구분됨. 유지보수 비용 최소 |
| 표면 규칙 — 테두리 대신 바탕 대비(canvas ↔ surface), 그림자는 상호작용 때만 | 조용하고 믿음직한 톤. 보안 검사·심사·메이커 정보처럼 신뢰가 필요한 화면에 맞음 |
| 색은 의미에만 — 배지·주요 행동 | 게임 아트가 이미 컬러풀하므로 UI 는 물러서야 함 |
| 같은 휘도에서 최대 채도로 색을 뽑는 방식 | 모든 강조색이 글자·배경 양쪽에서 AA 를 통과함을 계산으로 보장 |
| 큐레이션 문맥 — 왕좌 · 갓 나온 신작 · 숨은 보석 · 순삭 · 대전 | "고르는 재미"의 원형. 각 문맥이 근거 지표를 가짐 |
| 상태 인식 게임 상세(G1 기획) | 유입 경로별 도착 상태 분석이 정확함 |
| MakersGround 의 범위 — 잼·지원사업·질문·모집·출시 단계 | 한국어 온라인 인디 거점의 공백을 정확히 노림 |
| 구체적인 카피 — "재를 앞질러라. 단 90초." | 어느 사이트에도 붙일 수 없는 문장 |

## 3. 계승안 교정 규칙

### 3.1 색 — "쪽빛 · 인주"
기존 방식(같은 휘도 · 최대 채도)을 유지하되 목표 휘도를 Y=0.155 로 낮춰 **흰 바탕 5.12:1, canvas 4.7:1** 을 확보한다(기존 4.70 / 4.22). 계산: [`tools/palette.py`](tools/palette.py) · [`ramp.py`](tools/ramp.py) · [`neutral.py`](tools/neutral.py) → 디자인 시스템 단계에서 `docs/design/tokens` 로 이관.

| 토큰 | 값 | 의미 |
| --- | --- | --- |
| `accent` (play) — **쪽빛** | `#046DCE` · strong `#0159AA` · tint `#ECF4FE` | 플레이어. 한국 전통 남색(쪽) 계열의 맑은 파랑. blue-600(`#2563EB`)보다 덜 보랏빛 |
| `accent` (make) — **인주** | `#D22C02` · strong `#AD2201` · tint `#FEF0ED` | 메이커. 도장 찍는 인주의 주홍 — "만든 사람의 서명" |
| `ok` — 비취 | `#047F3F` · tint `#E5FAEA` | 검사 통과, 공개됨, 증가 |
| `danger` — 다홍 | `#DB0240` · tint `#FEEFEF` | 오류, 차단, 신고. 인주와 15° 차이라 **항상 아이콘 + 문장과 함께** 쓴다 |
| 중립(h255, 채도 거의 0) | canvas `#F3F4F6` · surface `#FFFFFF` · sunken `#EBEDF0` · line `#DDE0E3` · ink-1 `#151A20` · ink-2 `#4F5359` · ink-3 `#65696F` · ink-4 `#9B9FA3` | slate 대신 거의 무채색 흑연. **ink-3(메타 글자) canvas 5.09:1**, ink-4 는 글자 금지(아이콘·구분선 전용) |

- 기존 violet(도전과제)·magenta 는 폐기 — 의미 색은 2개(ok·danger) + 그라운드 accent 1개로 줄인다. 도전과제는 accent + DmD 기쁨 표정으로 표현.
- 다크 모드는 디자인 시스템 단계에서 같은 계산으로 도출.

### 3.2 표현층 — DmD 글자 얼굴
[01-concept-directions.md](01-concept-directions.md) 의 "글자로 만든 얼굴" 표정 체계를 채택한다. 표면 규칙(조용함) 위에 **얼굴만 움직인다** — 화면당 얼굴 하나, 상태가 바뀔 때만 표정 변화.

### 3.3 구조·밀도
1. 게스트에게 로그인 벽을 보여 주지 않는다 — 로그인 블록은 게스트 화면에서 빠지고 그 자리를 발견 동선이 채운다.
2. 홈 순서: 헤더(검색 포함) → 히어로(아트 우선, 수동 넘김) → [회원] 이어하기 한 줄 → 오늘의 픽(큐레이션 문맥) → 시간으로 고르기 → 새로 나온 게임(신작 보호 구좌) → 메이커 소식(개발일지) → 전체 게임.
3. 카드 정보는 4층으로 제한: 아트 / 제목 / 만든 사람(아바타 + 이름) / 한 줄 문맥(큐레이션 이유 또는 "장르 · 한 판 시간 · 실행"). 평점은 리뷰 10개 이상일 때만, 저장·이어하기는 아트 위 상태 표시.
4. 아이콘만으로 뜻을 전하지 않는다 — 실행 환경·인원은 글자로.
5. 히어로는 아트를 덮지 않는다 — 글자는 아트 바깥 또는 아트의 어두운 하단 스크림 위.
6. 지표는 행동을 돕는 숫자만(한 판 시간, 대기 인원, 진행률). 허영 지표(누적 플레이어 수)는 헤더·첫 화면에서 뺀다.
7. 반응형 필수: 데스크톱 1280 기준, 태블릿 768, 휴대폰 375. MakersGround 는 휴대폰을 먼저 그린다.

### 3.4 접근성 기준
WCAG 2.2 AA. 글자 4.5:1(24px 이상 3:1), 최소 글자 13px(메타) / 15px(본문), 포커스 링 2px 3:1, 터치 목표 44px, 자동 회전 없음, 호버 전용 정보 없음.

## 4. 표현층 — v3 피드백 이후 (2026-11-26)

v3(교정만 적용)에 대한 사용자 피드백: **"구조와 디자인이 단조롭고 어디서나 볼 수 있는 흔한 웹페이지."** 동의한다. 표현층을 뒤로 미룬 탓에, 리서치 02 의 "AI 느낌" 신호(#6 단일 서체, #10 균일 그리드, #13 섹션 리듬 동일)가 그대로 남았다. 비유를 덧씌우지 않고 **기능이 곧 모양이 되는** 장치 네 개로 정체성을 만든다.

### 4.1 글자 얼굴 — 자모 얼굴 아바타
한국 이모티콘 `ㅇㅅㅇ` `ㅎㅅㅎ` `ㅠㅅㅠ` 는 글자로 만든 얼굴이다. 로고 `DmD` 는 그 라틴 버전이다. 이 둘을 하나의 체계로 묶는다.
- **브랜드 얼굴**: `DmD` (D 두 개 회전 = 눈, m = 입). 시스템 상태 표정(기다림·기쁨·당황·졸림).
- **사람 얼굴**: 모든 사용자·메이커의 기본 아바타 = **이름 첫 자음을 눈으로, ㅅ 을 입으로** 쓴 자모 얼굴(픽셀상점 → `ㅍㅅㅍ`, 잿빛토끼 → `ㅈㅅㅈ`). 색 타일은 메이커 대표 게임에서 뽑는다. 첫 로그인 때 눈·입·색을 바꿔 "내 얼굴"을 만든다(R-ACCT-04).
- 효과: 사진 없는 플랫폼에서도 모든 사람에게 얼굴이 생긴다 → "만든 사람이 보이는 곳"이 아바타 단위에서 성립.

### 4.2 시간 자 — 한 판 시간을 축으로 한 지도
"시간으로 고르기"를 탭 + 그리드가 아니라 **0분 → 60분+ 눈금자 위에 게임을 꽂은 지도**로 그린다. 위치 자체가 정보(한 판 길이)다. 다른 플랫폼에 없는 화면이고, 웹 게이머의 짧은 세션 리듬(리서치 01)을 그대로 시각화한다.

### 4.3 게임색 필드 — UI 는 무채색, 색은 게임에서
UI 는 흑연 무채색 + 그라운드 강조색 하나로 조용히 두고, **큰 색면은 게임 아트의 대표색**으로 칠한다(히어로·픽 카드 바탕). 그래서 화면 색이 매주·매 슬라이드 바뀌고, 그 색의 출처는 항상 게임(=사람이 만든 것)이다. 업로드 시 대표색 추출(리서치 02 §5).

### 4.4 디스플레이 서체 — Gasoek One
본문·UI 는 Pretendard, **큰 목소리(히어로 헤드라인, 큐레이션 문맥 이름, 시간 자 숫자)** 는 Gasoek One(OFL, Google Fonts) — 두껍고 각진 한글 디스플레이. Z2(시그니처 영역)에서만, 화면당 2~3곳.

### 4.5 리듬 규칙
섹션마다 바탕(canvas / 게임색 필드 / 먹색 띠)과 배치(비대칭 · 눈금 · 인용)를 바꾼다. 같은 "제목 + 균일 그리드" 섹션은 연속 두 번 쓰지 않는다.

- **표정(글자 얼굴) 콘셉트 확정** — 사이트 심볼이자 모든 사용자 프로필 이미지 체계로 키운다.
- v4 는 "제품 소개 페이지 같고, 모두 큼지막해서 모바일 느낌". PC 는 **더 조밀하고, 웹 사이트·커뮤니티·인디게임 플랫폼다운 느낌**을 원한다. 모바일은 나중에 완전히 별도 디자인으로 가도 된다.

진단: v4 의 단일 열 + 56px 헤드라인 + 섹션당 한 화면 리듬은 랜딩 페이지 문법이다. PC 웹 커뮤니티·플랫폼(포털, 게임 커뮤니티, 인디 플랫폼)의 문법은 다르다.

### PC 레이아웃 원칙
1. **3단**: 좌측 탐색(장르·한 판 시간·실행·인원 — 개수 표시) / 가운데 본문 / 우측 사이드(로그인·내 정보, 랭킹, 공지, 잼). 컨테이너 1240px.
2. **포털식 헤더 3층**: 유틸 줄(그라운드 전환 · 공지 · 고객센터 · 로그인) → 로고 + 넓은 검색 → 메뉴 바(GNB).
3. **모듈 상자**: 흰 상자 + 상자 제목 15px + "더보기". 상자 안 목록은 1px 구분선.
4. **글자 크기**: 본문·목록 14px, 메타 13px, 상자 제목 15~16px, 페이지 최대 제목 30px 안팎. 큰 글자는 피처 배너 한 곳만.
5. **목록형 콘텐츠를 1급으로**: 게시판(제목 [댓글 수] · 작성자 얼굴 · 시각), 순위(번호 · 썸네일 · 등락), 작은 썸네일 그리드(4~5열).
6. **한 화면에 많은 입구**: 첫 화면(1080p) 안에 추천·순위·새 글·로그인이 함께 보인다.
7. **한국식 관습**: 순위 등락은 상승 빨강 ▲ · 하락 파랑 ▼, 공지 날짜, "더보기".
8. **정체성은 작게, 어디에나**: 자모 얼굴(목록마다 작성자 얼굴), 게임색(피처 배너), Gasoek One(큐레이션 문맥 단어·순위 숫자·시간 구간), 시간별 고르기(좌측 탐색 + 본문 모듈).

모바일 PlayGround 는 별도 디자인으로 후속. MakersGround 는 킥오프대로 모바일도 1급이므로 PC/모바일을 각각 설계한다.

### v5 피드백 이후 — 밀도는 유지, 문법은 요즘 것으로 (2026-11-26)

사용자 피드백: v5 는 원하던 PC 웹사이트 느낌은 달성했지만 **너무 복잡하고 아주 오래된 사이트 같다.** 필터를 좌측 사이드바에 둬서 본문 폭을 줄일 필요가 없고, 요즘은 사이드바가 없는 것이 흐름(넥슨, 카카오페이지 등). **트렌디함을 섞을 것.**

진단: 밀도를 만든 장치가 옛 포털의 것이었다 — 유틸 줄, 좌·우 사이드바, 흰 상자 위젯, 1px 구분선 목록, 곳곳의 "더보기 ›", 검색 범위 셀렉트 + 인기 검색어 줄.

**확정된 PC 원칙 (위 1~8 을 대체)**
1. **사이드바 없음** — 본문 한 열, 컨테이너 1280px 안팎을 끝까지 쓴다. 필터는 해당 섹션 안의 칩·탭으로.
2. **헤더 한 줄** — 로고 · 메뉴 · 그라운드 전환 · 검색 · 알림 · 얼굴. 스크롤 시 고정.
3. **밀도는 요즘 장치로** — 가로로 넘기는 줄(레일, ‹ › 버튼), 탭 달린 랭킹 격자(큰 순위 숫자), 5열 안팎의 촘촘한 카드 그리드.
4. **상자 대신 여백** — 바탕은 흰색, 섹션은 제목과 간격으로 구분. 회색 바탕 + 흰 상자 위젯 금지. 구분선은 최소.
5. **글자** — 섹션 제목 20~22px, 항목 제목 15px, 메타 13px. 큰 글자는 메인 배너 한 곳.
6. **배너** — 넓은 메인 배너(게임색 필드) + 양옆 다음·이전 배너가 살짝 보이는 캐러셀, 수동 넘김.
7. 정체성 요소(자모 얼굴·게임색·Gasoek One·시간으로 고르기)는 유지.

## 6. v6 확정 이후 개선 (2026-11-26)

사용자 평가: v6 가 지금까지 중 가장 좋음 — **PC 사이트 느낌과 트렌디함의 균형이 적당**. 로고 D 가 회전하며 표정이 바뀌는 것, 중간의 "로그인하면 내 얼굴이 생겨요" 띠가 좋음. → **v6 를 PC 기준 레이아웃으로 확정**하고 아래를 개선한다.

### 6.1 브랜드 얼굴 — 고양이 DmD
- D 를 기본으로 **회전시키지 않는다**(똑바로 선 D = 뜬 눈). `DmD` 위에 **귀 두 개와 이마 윤곽선만** 그려 고양이 얼굴로 만든다. `a` 는 얼굴 밖.
- 표정 = D 의 회전:
  | 상태 | D | 입 | 쓰는 곳 |
  | --- | --- | --- | --- |
  | 기본 | 똑바로 | m | 로고 |
  | 장난 · 기쁨 | 위로(◠, −90°) | w | 플레이 버튼 호버, 업적, 심사 통과, 저장 |
  | 시무룩 | 아래로(◡, +90°) | n | 404, 오류, 실행 실패 |
  | 놀람 | 똑바로 + 크게 | o | 로딩, 새 알림 |
  | 졸림 | 납작하게 | z | 점검, 빈 상태 |
- **가끔 저절로 움직인다**: 몇 초에 한 번 눈을 장난스럽게 굴리거나 흔든다. `prefers-reduced-motion` 이면 멈춘다.

### 6.2 그라운드 색 각인
PlayGround = 쪽빛, MakersGround = 인주. 색만 봐도 어느 그라운드인지 알 수 있어야 한다 → UI 를 무채색으로 두되, **각인 장치**에는 그라운드 색을 확실히 쓴다:
로고 귀, 활성 메뉴 밑줄, 로그인 버튼, 섹션 제목 앞 귀 표식, 큐레이션 배지, 배너 넘김 표시, 랭킹 띠(옅은 그라운드 색 바탕 + 순위 숫자), 로그인 띠(그라운드 색 바탕), 푸터 윗선. 게임 아트 영역에는 쓰지 않는다.

### 6.3 디테일
- **Gasoek One 은 28px 이상에서만**(배너 헤드라인, 순위 숫자, 잼 D-day). 작은 라벨에 쓰지 않는다 — "왕좌·신작"이 안 읽힌다는 피드백.
- **큐레이션 문맥 = 아이콘 + 글자 배지**를 아트 위에 얹고, 고른 이유는 큐레이터의 **말풍선**으로 아트 아래에 둔다(사람이 골랐다는 표현).
- **게임 카드**: 메이커 얼굴을 아트 왼쪽 아래 모서리에 얹어 "사람이 보이게", 호버 시 빠른 플레이 버튼.
- **플랫폼 표시(v2 계승·개선)**: 아트 오른쪽 위 칩에 아이콘 — 브라우저에서 바로 / 설치(다운로드) / PC / 휴대폰 / 패드 / 같이. 같은 아이콘을 필터 칩에서 범례로 쓰고, 칩마다 접근성 레이블을 단다(호버 전용 정보 금지 원칙 유지). 설치형 + 검사 통과는 방패 아이콘을 비취색으로.

### 6.4 나중에 할 것
- **자모 얼굴 개선**: 자음 수의 한계와 작은 크기에서 형태가 비슷해 보이는 문제 → 눈·입 외의 변수(귀·볼·눈썹·배경 무늬·고양이 귀 모양 등) 조합 방식을 추후 탐색.

### 6.5 문구 규칙 (v8 피드백, 2026-11-26)
사용자 피드백: "월화가 골랐어요", "이번 주 고른 게임", "게임 뒤의 사람과 과정" 같은 말은 **누가 골랐는지 묻게 만들고, 외국어를 옮긴 듯 어색하다.**
- **"누가 골랐다"는 표현을 쓰지 않는다.** 큐레이션은 "이번 주 PICK"처럼 한국 서비스에서 익숙한 말로. 카드 안에도 큐레이터 얼굴·이름·1인칭 말투를 넣지 않고, 사실만 담은 이유 한 줄("이번 주 플레이 수 · 완주율 모두 1위").
- **번역투 금지**: "~의 사람과 과정", "사람이 골라, 같이 노는 곳" 같은 명사 나열·직역체 대신 실제 한국 서비스 문구처럼 짧게. 섹션 부제는 정보가 없으면 생략.
- 상태 표기: "해봄" → "진행 45%", "친구 2명이 함" → "친구 2명이 플레이", 리뷰가 적으면 "아직 리뷰 3개"(권유 문장 붙이지 않음).
- 한 줄 소개(푸터 등): "광고 없는 인디 게임 플랫폼".

### 6.6 PICK 카드 바탕 · 실행 칩 툴팁 (v8 피드백)
- PICK 카드 바탕은 게임마다 다른 색이 아니라 **그라운드 색의 진한 톤 하나**(`--accent-deep`: 플레이 `#0D2B4D`, 메이커스 `#4A1A0C`)로 통일 — 섞인 색은 어수선하고, 통일하면 그라운드 색이 한 번 더 각인된다.
- **개정(v10)**: 카드에 배경색을 까는 것 자체를 쓰지 않는다(사용자 피드백). PICK 카드는 흰 바탕 위에서 **큰 그림(296px, 모서리 14px) + 문맥 배지 + 제목 18px + 쪽빛 표식이 붙은 이유 한 줄**로 일반 카드와 구분한다.
- 홈의 전체 게임 그리드는 **한 줄 4개**(카드 약 282px). 6열은 썸네일이 너무 작다.
- 썸네일 오른쪽 위 실행 칩은 **호버·키보드 포커스 시 aDmD 툴팁**(먹색 말풍선 + 화살표, 아이콘 + 설명 줄, 검사 통과는 비취색)을 띄운다. 브라우저 기본 `title` 툴팁 금지. 120ms 지연 후 표시, 구현 시 Esc 로 닫기(WCAG 1.4.13).
- 툴팁이 잘리지 않도록 썸네일은 `.art` 가 아니라 안쪽 이미지 층(`.shots`)만 잘라낸다.
