# 디자인 확정 순서 (2026-11-26 결정)

> 페이지는 캔버스 코드(`PG05` 등)로 부른다 — 목록: [canvas/README.md](canvas/README.md)

**결정**: 디자인을 모두 끝내고 개발하지 않는다. **핵심 흐름을 먼저 확정 → 개발 환경 마무리 + 디자인 시스템 코드화 → 디자인이 한 묶음 앞서 가며 구현.** 사용자가 아래 순서대로 화면을 확정한다.

## 1묶음 — 필수 (첫 구현 전에 확정)

플레이어가 "찾고 → 고르고 → 하고 → 다시 오는" 한 바퀴. 이게 없으면 서비스가 아니다.

| # | 캔버스 페이지 | 확정할 것 | 상태 |
| --- | --- | --- | --- |
| 1 | `DS01 기초` · `DS02 컴포넌트` · `DS03 컴포넌트 2` | 색 · 글자 · 헤더(테마 버튼) · 버튼 · 입력 · 상태 화면(404 · 오류) — 모든 화면의 바탕 | 검토 |
| 2 | `PG01 홈` | 홈 — 확정본에 다크 모드 · 고양이 얼굴만 더해짐, 다시 보기만 | 피드백 1차 반영(11/27) |
| 3 | `PG05 게임 상세` | Tweaks `state` 5종(처음 · 진행 중 · 완료 · 다운로드 · 이 기기 불가) · `tab` 4종 | v3 재설계(11/27) — 재검토 |
| 4 | `PG06 플레이 화면` · `PG07 플레이 종료` | 불러오기 · 플레이 · 일시정지 · 오류 · 종료 후 다음 행동 | 검토 |
| 5 | `SH01 로그인 · 내 얼굴 만들기` | 로그인 대화상자 · 고양이 얼굴 만들기 · 활동 공개 안내 | 검토 |
| 6 | `PG03 전체 게임` | 필터 · 정렬 · 결과가 적을 때 | 갤러리 v2(11/27 — 4열 · 태그 여러 개 · 무한 스크롤) — 재검토 |
| 7 | `PG14 내 라이브러리` | 이어하기 · 저장 · 기록 | 검토 |

> 1묶음 구현 때 게임은 운영자가 직접 넣는다(업로드 화면은 3묶음). 초기 콘텐츠 = 사용자 · 지인 게임.

## 진행 방식

- 사용자가 한 묶음을 확정하면, 그 묶음의 구현을 시작하면서 다음 묶음 확정을 받는다(디자인이 한 묶음 앞).
- 구현 중 드러나는 문제(반응형 · 상태 · 실제 데이터)는 캔버스와 문서에 바로 반영하고 사용자에게 알린다.
- 1묶음 확정과 함께: 개발 환경 마무리(컨벤션 · 브랜치 · 이슈) → `tokens.css` 와 공통 컴포넌트를 SvelteKit 으로.
