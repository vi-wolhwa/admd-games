# 0010. 장르 · 태그는 게임에서 생기고, 전체 게임은 무한 스크롤

- 상태: 확정 (2026-11-27, 사용자 요청에 따른 Claude 제안 — 되돌릴 수 있음)
- 화면: `PG03 전체 게임`, 앞으로 `MG04 업로드 마법사`(태그 입력) · `AD` 운영(태그 합치기)

## 1. 태그 — 빈 태그를 미리 만들지 않는다

**문제**: 초기에는 게임이 적어서 미리 만든 장르 · 태그 대부분이 비어 있게 된다. 쓰지도 않을 태그를 잔뜩 깔아 두면 필터가 허전하고 관리할 것만 늘어난다.

**전략: "게임이 태그를 만든다" + 운영자가 다듬는다**

| 규칙 | 내용 |
| --- | --- |
| 생성 | 메이커가 업로드 때 태그를 1~5개 적는다. 입력창은 **이미 있는 태그를 먼저 자동완성**으로 보여 주고, 없으면 새로 적을 수 있다. 새 태그는 **그 게임이 심사를 통과해 공개되는 순간** 생긴다(심사 중 · 반려 게임의 태그는 안 보임) |
| 보이는 조건 | 공개된 게임이 **1개 이상**인 태그만 필터에 나온다. 게임이 모두 내려가면 태그는 자동으로 숨는다(지우지 않음 — 다시 쓰이면 살아남) |
| 순서 | 게임 수가 많은 순. 필터 줄에는 상위 10개 + `태그 n개 더 보기` |
| 정리 | 같은 뜻(예: `퍼즐` · `퍼즐게임`)은 운영자가 **합치기**(옛 태그는 별칭으로 남겨 검색되게). 부적절한 태그는 숨김 |
| 씨앗 | 자동완성이 텅 비지 않게 운영자가 **기본 장르 8개 정도만** 처음에 넣는다(퍼즐 · 액션 · 탐험 · 전략 · 이야기 · 아케이드 · 리듬 · 경영). 이것도 게임이 0개면 필터에는 안 보인다 |

- 장르와 태그를 따로 두지 않는다 — 사용자에게는 하나의 "태그"로, 기본 장르는 처음부터 있던 태그일 뿐이다(개념 하나로 단순하게).
- 데이터: `tags(id, name, slug, alias_of)` + `game_tags(game_id, tag_id)` + 태그별 공개 게임 수 캐시(게임 공개 · 비공개 때 갱신 — 필터를 그릴 때마다 세지 않음, D1 읽기 절약).

## 2. 전체 게임 — 무한 스크롤 (페이지 번호 대신)

| | 무한 스크롤 | 페이지 번호 |
| --- | --- | --- |
| 둘러보기(갤러리) | **좋음** — 그림을 계속 넘겨 보는 행동에 맞음(카카오페이지 · 라프텔 같은 방식) | 끊김 |
| 특정 위치로 돌아오기 | 상세에서 뒤로 가기 때 위치 복원이 필요 → 구현으로 해결 | 쉬움 |
| 초기 게임 수(수십~수백) | 몇 번만 불러오면 끝까지 감 → 바닥글도 닿음 | 페이지가 몇 개 안 돼 어색 |
| 무료 플랜 D1 | 커서 방식이면 `OFFSET` 스캔 없음 | `OFFSET` 이 깊어질수록 읽기 증가 |

**결정: 무한 스크롤.** 구현 규칙:
- 목록 끝 600px 전에 `IntersectionObserver` 가 다음 12개를 부른다. **커서 방식**(마지막 항목의 정렬 값 + id) — `OFFSET` 쓰지 않음.
- 불러오는 동안 같은 크기의 빈 카드(스켈레톤) 한 줄 + "12개 더 불러오는 중 · 24 / 46". 끝나면 "46개 모두 봤어요".
- 필터 · 정렬 · 불러온 개수는 URL 에 남긴다(새로 고침 · 공유 · 뒤로 가기에 그대로). 상세에서 돌아오면 스크롤 위치 복원(SvelteKit snapshot).
- 오른쪽 아래 `맨 위로` 버튼. 키보드 사용자를 위해 목록 맨 아래에 `더 불러오기` 버튼도 둔다(관찰자가 안 될 때의 대체 — 보이는 '더 보기' 버튼으로 운영하지는 않음).
- 같은 규칙을 검색 결과(`PG04`)에도 쓴다.
