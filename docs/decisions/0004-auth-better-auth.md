# 0004. 인증: better-auth (게스트 익명 → OAuth 연결)

- 상태: 승인 (2026-11-26, 사용자 승인) — 구현은 해당 이슈에서
- 등급: A

## 배경

로그인 없이 바로 플레이하고(게스트), 원할 때 소셜 계정으로 연결해 기록을 보존하는 흐름이 필요하다. 무료여야 하고 DB 교체 시 함께 옮길 수 있어야 한다.

## 선택지

| 후보 | 장점 | 단점 |
| --- | --- | --- |
| **better-auth** | 오픈소스·자체 호스팅(무료), `anonymous` 플러그인 + 계정 연결 훅, Drizzle 어댑터로 D1 사용 | 인증 테이블을 직접 관리 |
| Supabase Auth | 익명 로그인·OAuth 내장 | Supabase 종속, 무료 프로젝트 일시정지 |
| Clerk / Auth0 | 관리형, UI 제공 | 무료 한도 후 유료, 강한 종속 |
| Auth.js | 오픈소스 | 익명 → 계정 승격을 직접 구현해야 함 |

## 결정

better-auth 를 쓴다. 로그인 수단은 **익명(게스트) + OAuth(GitHub, Google 우선)** 로 시작하고 이메일·비밀번호는 넣지 않는다.

## 이유

무료·자체 호스팅이라 종속이 없고, 게스트 → 정식 계정 승격을 플러그인으로 지원한다. 비밀번호 해싱은 Workers 무료 플랜의 CPU 10ms 한도를 넘길 수 있어 제외한다.

## 결과

- 인증도 포트 뒤에 둔다(라우트는 세션 조회 인터페이스만 사용).
- OAuth 앱 등록(GitHub·Google 무료)은 사용자가 직접 하고, 클라이언트 ID/시크릿은 `wrangler secret` 과 로컬 `.dev.vars` 로만 관리한다.
- 2026-11-28(사용자): 게스트(익명)와 합치기는 PG06 에서 — 처음 저장할 것이 생길 때, 처음 저장할 때만 게스트를 만든다. SH01 은 OAuth 만. 미리보기 · 로컬에는 테스트 로그인(운영 차단).
