# 0013. 브랜치 모델 · 자동 배포 · 저장소 공개

- 상태: 승인 (2026-11-27, 사용자 결정)
- 바꾸는 것: [0005](0005-repository-and-workflow.md) 의 "비공개 저장소", "GitHub Flow(main 하나)"

## 결정

| 항목 | 결정 |
| --- | --- |
| 브랜치 | `feat/…` · `fix/…` · `chore/…` · `docs/…` → PR → **`develop`**(확정된 작업이 쌓임, PR 미리보기로 확인) → '내보내기' PR → **`main`** |
| 배포 | **`main` 병합 = 운영 자동 배포.** 내보내기 PR 승인 = 배포 승인. 하루의 a · b · c 가 한 번에 나감(ADR 버전 규칙과 맞음 — v1.0 이후 내보내기 = 릴리스) |
| 직접 푸시 | `main` · `develop` 직접 푸시 금지. **`main` 으로는 `develop` 만 PR 가능** |
| 강제 수단 | 저장소를 **공개**로 바꿔 GitHub 규칙 세트(무료)를 쓴다: main = PR 필수 · 'develop 에서 온 PR' 검사 필수 · 강제 푸시 · 삭제 금지 / develop = PR 필수 · CI 필수. 추가로 커밋 훅이 로컬 직접 푸시를 막고, 배포 작업도 커밋 출처를 확인 |
| 저장소 공개 | **공개** — 사용자 결정. 알림은 팔로워에게 가지 않지만 활동 · 코드 · 문서가 모두 공개됨을 안내함 |
| 공개 전 정리 | ① 비밀값 검사(전체 이력) — 없음 ② 작성자 이메일 — 사용자 결정으로 그대로 공개 ③ 참고 그림(`docs/design/archive/canvas/uploads`, 타사 게임 화면 포함) — **이력에서 완전히 제거**(강제 푸시 승인됨) |
| 라이선스 | 바꾸지 않음 — 라이선스 없음(모든 권리 보유): 코드는 보이지만 다른 사람이 쓸 권리는 없음 |

## 덤으로 생기는 것

- 공개 저장소는 GitHub Actions 표준 러너가 **무료 · 무제한** → CI 분 걱정이 사라짐(바뀐 것만 돌리는 원칙은 속도 때문에 유지).
- 규칙 세트 · 필수 검사 · 필수 PR 이 실제로 강제됨.

## 주의

- 이력에서 지운 커밋도 GitHub 에서 SHA 로 직접 접근하면 한동안 보일 수 있다(참조가 없어 찾기 어려움). 필요하면 GitHub 지원에 정리 요청.
- 다른 기기에 옛 이력의 클론이 있다면 다시 클론해야 한다.
