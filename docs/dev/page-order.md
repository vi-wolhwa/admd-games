# 페이지 구현 순서 (2026-11-27, Claude 설계 — 사용자 검토용)

원칙: ① 플레이어의 한 바퀴(찾기 → 고르기 → 하기 → 다시 오기)를 먼저 ② 많이 재사용될 컴포넌트 · 데이터 모델을 **먼저 만드는 페이지**가 앞 ③ 다른 것을 모으기만 하는 페이지(홈)는 재료가 다 생긴 뒤 ④ 로그인이 필요한 행동은 로그인 직전 페이지까지는 '게스트 상태'로 만들고 로그인 페이지에서 켠다.

| 순서 | 페이지 | 이 페이지가 처음 만드는 것(다음 페이지들이 재사용) | 앞 페이지에 기대는 것 |
| --- | --- | --- | --- |
| 1 | **PG03 전체 게임** | 사이트 헤더 · 푸터 · 레이아웃(Play), 기본 부품(Button · Chip · Tag · Badge · Tooltip · Icon · Dropdown · Skeleton · CatFace), 게임 카드 · 실행 칩 · 추천/리뷰 수, 게임 목록 데이터(포트 · D1 · 가짜 데이터), 태그 집계, 커서 무한 스크롤 | — |
| 2 | **PG05 게임 상세** | 미리보기(자동 넘김) · 게임 패널(상태 기계 `playAction`) · 핵심 칸 · 키-값 목록 · 붙는 탭 · 리뷰(EntryShell 패턴 · ReviewItem) · 메이커 카드 · 문제 알리기 대화상자(Bits UI 첫 사용) | 헤더 · 카드(비슷한 게임) |
| 3 | **SH01 로그인 · 내 얼굴 만들기** | better-auth(게스트 → OAuth), 세션 · 권한 규칙, 고양이 얼굴 만들기 — 여기서 PG05 의 추천 · 즐겨찾기 · 리뷰 쓰기를 켬 | 헤더(로그인 상태) |
| 4 | **PG06 플레이 화면** | 게임 별도 출처 · `<iframe sandbox>` · 플레이 기록(시작 · 끝) · SDK 메시지 첫 판(진행도) | 로그인(기록 주인) |
| 5 | **PG07 플레이 종료** | 다음 게임 추천 · 추천하기 · 리뷰 한 줄 | 카드 · 추천 · 리뷰 |
| 6 | **PG14 내 라이브러리** | 최근 플레이 · 즐겨찾기 · 설치형 · 기록 목록 | 플레이 기록 · 즐겨찾기 |
| 7 | **PG01 홈** | 배너 캐러셀 · PICK 레일 · 주간 랭킹(미리 계산) · '몇 분 있어요' · 최근 플레이 줄 — 대부분 조립 | 거의 모든 앞 페이지 |
| 8~ | 2묶음: PG04 검색 → PG13 메이커 → PG10 리뷰 전체 → SH03 알림 → SH02 설정 → SH04 신고 → PG15 프로필 → PG02 지난 PICK → PG08/09 설치형 · 보안 리포트 → 모바일 | | |
| … | 3묶음(MakersGround) · 4묶음(운영) — 그 단계에서 다시 순서 설계 | | |

- 디자인 시스템(DS01~DS04)은 따로 페이지로 만들지 않고, 1번 페이지를 만들면서 갤러리의 `Primitives` · `Patterns` 로 자연스럽게 생긴다.
- 각 페이지는 캔버스 시안을 출발점으로 삼되, 그동안의 결정(ADR 0009~0011)과 다른 곳은 결정이 우선.
