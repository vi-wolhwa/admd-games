## 6-6 분석 — 의존성 업데이트 (Claude 결정, 2026-11-27)

현실의 회사들은 "매주 PR"보다 ① 보안 패치는 바로 ② 나머지는 월 단위로 묶어서 ③ 메이저 업데이트는 계획된 작업으로 다룬다. 우리 조건: 1인 + Claude, 비공개 저장소(CI 무료 2,000분/월), 공급망 7일 숙성 규칙, 외부 서비스에 저장소 접근을 주지 않는 편이 안전.

| 결정 | 이유 |
| --- | --- |
| **Dependabot**(GitHub 내장) 사용, Renovate 는 쓰지 않음 | Renovate 는 외부 앱에 비공개 저장소 접근을 줘야 함. Dependabot 은 GitHub 안에서 끝남 |
| **보안 업데이트는 즉시**(Dependabot security updates) | 알려진 취약점은 기다릴 이유가 없음 |
| **일반 업데이트는 한 달에 한 번, minor · patch 를 한 PR 로 묶음** + 7일 대기(cooldown) | 주 1회는 1인 프로젝트엔 소음. 한 달 묶음 하나면 검토 · CI 가 한 번 |
| **메이저는 자동 PR 에서 제외** → 나오면 이슈 하나로 계획(이관 안내 읽고 브랜치에서 작업) | SvelteKit · Vite · Tailwind 메이저는 코드 수정이 필요한 작업이지 '업데이트 버튼'이 아님 |
| 의존성 PR 은 **전체 CI** | 영향 범위가 앱 전체라 '바뀐 것만' 규칙의 예외 |
