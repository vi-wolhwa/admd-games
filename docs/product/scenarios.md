# 사용 시나리오 시뮬레이션

가상의 사람 7명이 aDmD Games 를 처음부터 끝까지 쓰는 과정을 한 단계씩 따라가며, 각 단계에서 **화면이 반드시 해 줘야 하는 것**을 요구사항(R-…)으로 뽑았다. 페이지 목록은 [pages.md](../design/pages.md), 출시 범위 확정은 PRD 에서 한다.

- 출시 표기: **L1** = 첫 출시에 필요, **L2** = 출시 직후 후속, **L3** = 나중 (PRD 에서 확정)
- 근거: [킥오프](kickoff.md) — 만든 사람이 보이는 곳 · 고르는 재미 · 같이 노는 곳 · 다운로드 신뢰 · 누구나 업로드 · PC 우선 + 모바일(MakersGround 는 모바일 1급) · 한국어

## 등장인물

| 코드 | 사람 | 상황 | 기기 |
| --- | --- | --- | --- |
| P1 | 민지, 대학생 | 친구가 단톡방에 던진 게임 링크로 처음 들어옴. 가입할 생각 없음 | 휴대폰 → 저녁에 노트북 |
| P2 | 준호, 직장인 | 2주째 단골. 점심시간에 짧게, 주말엔 친구와 | 회사 PC, 집 PC |
| P3 | 서연, 고등학생 | 다운로드 게임이 궁금하지만 바이러스가 걱정됨. 부모님 PC | Windows PC |
| P4 | 도윤, 1인 개발자 | 첫 게임(웹빌드)을 올리고 싶음. 출퇴근길에 반응 확인 | 노트북 + 휴대폰 |
| P5 | 픽셀상점, 3인 스튜디오 | 게임 3개 운영. 업데이트·개발일지·잼 참가 | PC 위주, 알림은 휴대폰 |
| P6 | 운영자(본인) | 심사, 신고 처리, 큐레이션 발행 | PC + 휴대폰 |
| P7 | 하은, 잼 참가자 | 게임잼에 팀으로 나가고 싶음. 질문하고 팀원 구함 | 휴대폰 위주 |

## A. 발견하고 플레이하기

### S01. 공유 링크로 처음 들어와 바로 플레이 — P1, 휴대폰

1. 단톡방 링크 미리보기를 본다 → **R-SHARE-01** 게임별 공유 카드(OG 이미지: 아트 + 제목 + 메이커 + aDmD 얼굴 마크) L1
2. 링크를 누르면 홈이 아니라 그 게임 상세로 도착 → **R-DETAIL-01** 상세는 그 자체로 첫 페이지 역할(사이트가 뭔지 한 줄 + 로그인 요구 없음) L1
3. 휴대폰인데 이 게임은 키보드 전용 → **R-DETAIL-02** 첫 화면에서 "이 기기에서 되는지"를 판정해 말해 줌 (가능/터치 미지원/PC 전용) L1
4. 지금 못 하니 저녁에 노트북에서 하고 싶다 → **R-LATER-01** 로그인 없이 "나중에 하기": 링크 복사·나에게 보내기(카톡 공유 시트) / 게스트 라이브러리(이 기기에 저장, 로그인 시 병합) L1
5. 저녁, 노트북에서 같은 링크 → 상세 → 플레이 → **R-PLAY-01** 게스트도 즉시 플레이(가입 벽 없음) L1
6. 게임 로딩 → **R-PLAY-02** 로딩 중 게임 정보·조작법을 보여 주는 대기 화면, 진행률, 실패 시 다시 시도 L1
7. 다 하고 나왔다 → **R-PLAY-03** 플레이 종료 화면: 이 게임 어땠는지 한 번 탭 반응, 만든 사람 소개 + 팔로우, 비슷한 게임, 기록 저장 유도 L1
8. 점수가 꽤 높다 → **R-ACCT-01** "기록을 남기려면 계정 연결" — 이 기기 게스트 기록을 잃지 않고 연결(GitHub·Google) L1

### S02. 홈에서 고르는 재미 — P2, 회사 PC 점심시간

1. 홈 진입 → **R-HOME-01** 홈의 첫 화면은 "이번 호" 편집 큐레이션(주제·짧은 글·고른 사람). 그리드가 아니라 읽히는 지면 L1
2. 시간이 15분 → **R-DISC-01** "한 판 시간"으로 고르기(5분 이하·15분·30분+) L1
3. 이어하던 게임이 있다 → **R-HOME-02** 로그인 사용자에게 "이어하기" 한 줄을 히어로 위/옆에 (게스트에겐 없음, 빈 자리 없음) L1
4. 큐레이션 카드에 "왜 골랐는지" 한 문장 → **R-CURA-01** 모든 큐레이션 항목에 추천 이유 + 고른 사람 L1
5. 컬렉션(예: "퇴근길 한 손 게임") → **R-CURA-02** 테마 컬렉션 페이지 (편집자·메이커·사용자가 만든 목록) L1(편집자) / L2(사용자)
6. 친구가 최근 한 게임 → **R-SOCIAL-01** 홈에 친구 활동 한 줄 (친구 있을 때만) L2
7. 마음에 드는 게임을 저장 → **R-LIB-01** 저장(찜) 토글 — 카드·상세·플레이 종료 화면 어디서나 L1

### S03. 탐색·검색 — P2

1. 전체 게임 보기 → **R-DISC-02** 카탈로그: 장르, 플레이 방식(브라우저/다운로드), 인원(싱글/멀티/협동/대전), 한 판 시간, 지원 기기, 조작(키보드/마우스/터치/패드), 정렬(새로 나옴·많이 함·평가 좋음·업데이트) L1
2. 필터를 조합하고 링크로 공유 → **R-DISC-03** 필터 상태가 URL 에 남음 L1
3. "픽셀" 검색 → **R-SRCH-01** 통합 검색: 게임·메이커·태그·개발일지를 구분해 보여 줌, 오타·초성(ㅍㅅ) 대응 L1(게임·메이커·태그) / L2(초성·글)
4. 결과 없음 → **R-SRCH-02** 빈 결과에서 조건 완화 제안 + 큐레이션으로 출구 L1
5. 게임 수가 적은 초기 → **R-DISC-04** 카탈로그가 비어 보이지 않는 레이아웃(적을 때는 큰 카드·편집형, 많아지면 그리드) L1

### S04. 게임 상세에서 결정 — P1·P2

1. 첫 화면에서 판단할 것 3가지: 어떤 게임인지(움직이는 화면), 지금 되는지(기기·시간), 누가 만들었는지 → **R-DETAIL-03** 히어로 = 영상/움직이는 미리보기(없으면 스크린샷) + 실행 조건 + 메이커 얼굴 L1
2. 이미 하던 게임 → **R-DETAIL-04** 상태 인식 CTA: 처음(지금 플레이) / 진행 중(이어하기 + 내 진행) / 완료(다시 하기 + 기록) / 다운로드(다운로드) / 멀티(같이 하기) L1
3. 스크린샷 → **R-DETAIL-05** 갤러리 + 라이트박스(키보드 ← → Esc) L1
4. 리뷰가 궁금 → **R-REVIEW-01** 평점 분포 + 리뷰(플레이 시간 표시) + 메이커 답글 L1
5. 만든 사람 → **R-MAKER-01** 상세 안에 "만든 사람" 블록: 사진/아바타, 한 줄 소개, 최근 개발일지 1개, 다른 게임, 팔로우 L1
6. 업데이트 내역 → **R-DETAIL-06** 버전·패치노트 L1
7. 도전과제·리더보드 → **R-DETAIL-07** 도전과제 목록(달성률), 리더보드 상위 + 친구 순위 L2
8. 신고 → **R-SAFE-01** 게임 신고(부적절·저작권·악성·작동 안 함) L1
9. 연령·콘텐츠 표시 → **R-SAFE-02** 메이커가 입력한 콘텐츠 표시(폭력·공포·선정성 등) + 필요 시 확인 화면 L1

### S05. 플레이 화면 — P2, PC

1. 플레이 시작 → **R-PLAY-04** 플레이 셸: 게임 영역 최대화, 상단 얇은 바(제목·메이커·전체화면·소리·도움말·신고·나가기) L1
2. 방향키를 눌렀더니 페이지가 스크롤 → **R-PLAY-05** 게임 포커스 시 키 입력 가둠, Esc 로 포커스 해제·일시정지 L1
3. 다른 탭으로 → **R-PLAY-06** 자동 일시정지·음소거 (SDK 사용 게임) L1
4. 게임이 멈춤 → **R-PLAY-07** 오류 화면: 다시 불러오기, 문제 신고(환경 정보 자동 첨부) L1
5. 도전과제 달성 → **R-PLAY-08** 플랫폼 공통 토스트(게임 위에 겹치되 조작 방해 없음) L2
6. 나가기 → S01-7 종료 화면 L1

### S06. 다운로드 게임과 신뢰 — P3, Windows

1. 상세에서 "다운로드" CTA 와 함께 **보안 검사 배지** → **R-TRUST-01** 파일마다 검사 상태(검사 완료·문제 없음 / 검사 중 / 주의 / 차단)와 검사 시각·엔진 L1
2. 배지를 눌러 리포트 → **R-TRUST-02** 검사 리포트 페이지: 파일명·크기·해시(SHA-256)·검사 엔진·결과·버전별 이력, 쉬운 말 설명 L1
3. 다운로드 → **R-DL-01** 플랫폼별 파일 선택(Windows/macOS/Linux/Android), 용량, 버전, 요구사양 L1
4. "Windows 가 경고를 띄워요" → **R-DL-02** 설치 안내(SmartScreen 등 경고 설명, 서명 여부 표시) L1
5. 몇 주 뒤 새 버전 → **R-DL-03** 라이브러리에서 "업데이트 있음" + 알림 L2
6. 검사에서 문제 발견 → **R-TRUST-03** 해당 파일 다운로드 차단, 메이커에게 사유 통지, 플레이어에겐 "검사 중 문제가 있어 내려받을 수 없습니다" L1

### S07. 계정 — P1

1. 연결 시작 → **R-ACCT-02** 로그인 = 모달(페이지 이동 없음), GitHub·Google·(Discord L2) L1
2. 연결 후 → **R-ACCT-03** 게스트 기록·저장 목록 병합 결과 알림 L1
3. 첫 로그인 → **R-ACCT-04** 닉네임 + 아바타 정하기(기본: aDmD 얼굴 표정 아바타 생성기) — 건너뛰기 가능 L1
4. 설정 → **R-ACCT-05** 프로필 편집, 연결 계정, 알림 설정, 공개 범위(활동·라이브러리 공개 여부), 데이터 내보내기, 탈퇴 L1

### S08. 내 라이브러리와 기록 — P2

1. 라이브러리 → **R-LIB-02** 이어하기 / 저장함 / 다운로드함 / 플레이 기록(시간·최근) 탭 L1
2. 진행 상황 → **R-LIB-03** 게임별 플레이 시간, 마지막 플레이, 도전과제 n/m L1(시간) / L2(도전과제)
3. 다른 PC → **R-LIB-04** 클라우드 세이브가 있는 게임은 이어서 (SDK) L2
4. 내 프로필 → **R-PROF-01** 공개 프로필: 대표 게임, 최근 플레이, 리뷰, 도전과제, 팔로우 중인 메이커 L1(기본) / L2(도전과제)

### S09. 같이 놀기 — P2 주말

1. 친구 추가 → **R-SOCIAL-02** 친구 = 서로 수락. 초대 링크·닉네임 검색 L2
2. 같이 할 게임 → **R-SOCIAL-03** 멀티 게임 "같이 하기": 방 만들기 → 초대 링크/방 코드 → 대기실(참가자·준비·채팅 이모지) → 시작 L2
3. 친구가 접속 중 → **R-SOCIAL-04** 친구 상태(온라인·지금 하는 게임 — 공개 설정 따름) L2
4. 랭킹 → **R-RANK-01** 게임별 리더보드(주간·전체·친구) L2
5. "같이 노는 곳" 의 출시 최소치 → **R-SOCIAL-05** 플레이 종료 화면·상세에서 "친구에게 도전장"(내 점수 + 링크 공유) L1

### S10. 리뷰 — P2

1. 리뷰 쓰기 조건 → **R-REVIEW-02** 플레이 기록이 있어야 작성(다운로드 게임은 다운로드 기록), 한 게임 1리뷰 수정 가능 L1
2. 형식 → **R-REVIEW-03** 추천/비추천 + 짧은 글 + 태그 선택("짧고 굵음", "친구랑" 등) L1
3. 메이커 답글 → **R-REVIEW-04** 메이커 답글 표시·알림 L1
4. 신고 → **R-SAFE-03** 리뷰 신고 L1

### S11. 만든 사람 만나기 — P1·P2

1. 상세 → 메이커 이름 → **R-MAKER-02** 메이커 페이지(개인/팀): 소개, 게임, 개발일지, 진행 중 프로젝트, 링크, 팔로우 수 L1
2. 팔로우 → **R-MAKER-03** 팔로우한 메이커의 새 게임·업데이트·개발일지가 홈과 알림에 L1
3. 응원 → **R-MAKER-04** 결제 없는 응원: 플레이 후 "응원 한마디"(메이커에게만 보이는 짧은 메시지) / 개발일지 반응 L2

### S12. 알림 — P2·P4·P5

1. **R-NOTI-01** 알림 센터(헤더 종) — 종류: 팔로우 메이커 소식, 내 리뷰 답글, 친구, 심사 결과, 신고 처리 결과, 공지 L1
2. **R-NOTI-02** 알림 설정(종류별 켜기/끄기, 이메일 여부 L2) L1

## B. 만들고 올리기 (MakersGround)

### S13. 첫 게임 올리기 — P4

1. PlayGround 푸터·헤더의 "게임 올리기" → **R-MK-01** MakersGround 첫 방문 안내: 무엇을 올릴 수 있는지(웹 빌드 zip, 다운로드 파일), 규칙, 걸리는 시간 L1
2. 메이커 프로필 만들기 → **R-MK-02** 개인/팀 프로필(팀원 초대 L2) L1
3. 새 게임 → **R-MK-03** 업로드 마법사(저장하며 진행, 모바일에서도 이어서):
   ① 기본 정보(제목·한 줄 소개·장르·태그) ② 실행 방식(브라우저 zip / 다운로드 파일, 플랫폼) ③ 빌드 업로드(진행률·용량 한도·형식 검사) ④ 미리보기 테스트(실제 플레이 셸에서) ⑤ 화면(대표 아트 규격, 스크린샷 3~8, 영상 링크) ⑥ 상세 정보(한 판 시간, 인원, 조작, 지원 기기, 콘텐츠 표시, 언어) ⑦ 공개 설정(공개/링크 공유만/비공개, 공개 예약) ⑧ 제출 L1
4. 이미지 규격 맞추기 어려움 → **R-MK-04** 아트 업로드 시 크롭 미리보기(카드·히어로·공유 카드에서 어떻게 보이는지) L1
5. 제출 → **R-MK-05** 자동 검사(악성코드·용량·필수 항목·실행 확인) → 결과 즉시 표시 L1
6. 심사 → **R-MK-06** 게임 상태 단계: 작성 중 → 검사 중 → 심사 대기 → 공개 / 보완 요청(사유·수정할 곳 링크) / 반려 L1
7. 출퇴근길에 확인 → **R-MK-07** 모바일에서 상태 확인·알림·간단 수정(텍스트·공개 설정) L1

### S14. 게임 업데이트 — P5

## 시뮬레이션에서 발견한 설계 원칙

1. **게스트에게 벽을 보여 주지 않는다.** 로그인이 필요한 블록은 게스트 화면에서 빠지고, 그 자리는 발견·플레이 동선이 채운다. 로그인 요청은 기록을 잃을 순간(점수·저장)에만.
2. **게임 옆에는 항상 사람이 있다.** 카드·상세·플레이 종료·검색 결과 어디서든 메이커가 이름 이상의 존재감(얼굴·한 줄)을 가진다.
3. **모든 추천에는 이유가 있다.** 알고리즘 같은 "추천 게임" 대신, 누가 왜 골랐는지 쓴다.
4. **신뢰는 보여 준다.** 검사 결과·심사 상태·버전 이력을 숨기지 않고 쉬운 말로 노출한다.
5. **끝은 다음의 시작.** 플레이 종료 화면이 반응·메이커·다음 게임·친구 도전으로 이어지는 허브.
6. **기기를 정직하게.** 지금 이 기기에서 되는지 먼저 말하고, 안 되면 다른 기기로 넘기는 길을 준다.
